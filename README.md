## 📱 How Pairing Works (Web Panel)

Pairing is done entirely through the bundled **web pairing panel** — no
console access needed, no QR scanning.

1. Deploy the bot (see Render section below, or run locally / on a VPS).
2. Open the panel in your browser: `http://localhost:3000/panel/index.html`
   (or your Render URL, e.g. `https://your-app.onrender.com/panel/index.html`).
3. Go to **Deploy Bot**, enter your WhatsApp number with country code,
   solve the security check, and tap **Generate Pairing Code**.
4. You'll get an 8-character code:

```bash
XXXX-XXXX
```

5. Open WhatsApp on your phone:

```
WhatsApp
└── Linked Devices
    └── Link a device
        └── Link with phone number instead
```

6. Enter the pairing code.
7. Session is automatically saved inside:

```bash
./sessions/<number>/
```

and reconnects automatically after restart.

Head to **Manage Bots** on the panel any time to see how many numbers are
paired (shown masked, e.g. `234901**678`, never in full) or to unlink a
number you own by entering it in full.

> Telegram is informational only now (`/start`, `/menu`, `/help` — it
> just links to the web panel and official channels). All pairing-code
> generation happens on the web panel.

## ⚡ Non-Interactive Pairing (still supported)

If you'd rather pair on boot without the web panel, you can still use:

```env
PAIR_NUMBER=2349127857212
```

before starting the bot. The pairing code will be printed once in the logs.

## ☁️ Render Deployment

This repo includes a `render.yaml` blueprint, so you can deploy with one click:

1. Push this repo to your own GitHub.
2. On Render: **New → Blueprint**, point it at your repo.
3. Render reads `render.yaml` and creates a **Web Service** automatically
   (build: `npm install`, start: `node index.js`).
4. Set any optional env vars in the Render dashboard:

| Variable | Description |
|-----------|-------------|
| `OWNER_NUMBER` | Owner WhatsApp number |
| `TELEGRAM_TOKEN` | Optional — enables the informational Telegram bot |
| `PANEL_URL` | Your deployed panel URL, shown as a button in Telegram |
| `CAPTCHA_SECRET` | Auto-generated by Render; used to sign the security check |
| `OPENAI_API_KEY` / `WEATHER_API_KEY` | Optional integrations |

5. Once deployed, open `https://<your-app>.onrender.com/panel/index.html`
   and pair your first number from **Deploy Bot**.

Render automatically provides the `PORT` env var — the app listens on it,
so the health check and panel work out of the box.

> **Note:** Render's free tier spins down idle web services and wipes the
> filesystem on redeploy, which will drop `./sessions/`. For 24/7 uptime
> with persistent sessions, use a paid Render plan with a persistent disk,
> or a VPS.

## 💻 Local / VPS Deployment

```bash
git clone <your-fork>
cd sukuna-md

npm install --omit=dev

# Starts the bot + Telegram bridge (if configured) + web panel together
node index.js
```

Then open `http://localhost:3000/panel/index.html` (or your `$PORT`) to pair.

Recommended process managers:

```bash
pm2
systemd
screen
```
